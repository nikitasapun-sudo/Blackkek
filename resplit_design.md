# План generic SPLIT с повторным разделением

Этот документ описывает следующий вариант математического ядра. Он не меняет текущую реализацию `solveSplit`, которая остаётся точной моделью двух рук без повторного разделения. Цель плана — получить общий конечноколодный расчёт для одной исходной пары, повторного SPLIT и заданного ограничения на число рук.

## Границы первой реализации

Первый вариант должен принимать явный параметр `maxSplitHands`.

| Значение | Поведение |
|---:|---|
| `1` | SPLIT недоступен |
| `2` | Текущая модель без повторного разделения |
| `3` | Разрешена одна дополнительная рука |
| `4` | Максимум четыре руки, обычный учебный режим resplit |

Значения больше `4` следует отклонять до появления отдельного анализа памяти и времени. Для совместимости `resplit:false` означает `maxSplitHands:2`, а `resplit:true` должно означать `maxSplitHands:4` только в новом режиме. Лучше сохранять в диагностике нормализованное значение и не полагаться на неявный флаг.

Ограничение относится к общему числу активных и уже созданных рук одной раздачи. Повторный SPLIT разрешён только если после него число рук не превысит `maxSplitHands`. Отдельный параметр `resplitAces` нужен для правил, где тузы нельзя разделять повторно; по умолчанию он `false`.

## Состояние раздачи

Вместо фиксированных `first` и `second` нужен рекурсивный информационный state:

```text
state = {
  shoe: rankCounts,          // скрытая карта дилера ещё находится в остатке
  queue: [HandState, ...],   // руки в порядке розыгрыша
  finished: [HandState, ...],// терминальные руки, ждут общего settlement
  handsCreated: number,      // всего создано рук, включая finished
  nextHandId: number,
  splitCount: number
}

HandState = {
  cards: up to two normalized ranks, // 10/J/Q/K хранятся как общий bucket 10
  total: number,
  softAces: number,
  length: number,
  bet: 1 | 2,
  fromSplit: boolean,
  splitDepth: number,
  needsCard: boolean,             // новая часть SPLIT ещё не получила карту
  aceSplit: boolean,
  handId: number
}
```

Для обычной начальной руки `fromSplit:false`, `bet:1`, `needsCard:false`. При SPLIT исходная пара удаляется из текущей руки и превращается в две руки с одной картой и `needsCard:true`. Публичная карта для первой части выдаётся до её решения; после завершения первой части карта для второй части выдаётся из того же остатка. Это сохраняет последовательность конечной колоды и видимую информацию игрока.

В ключ memo нельзя включать только сумму. Для возможности resplit нужны как минимум `cards` для руки длиной два, `total`, `softAces`, `length` когда включены Charlie или DAS, `bet`, `fromSplit`, `splitDepth`, `needsCard`, очередь в точном порядке, список `finished` и весь вектор остатка. `handId` не влияет на математику и в ключ не входит. Нельзя сортировать очередь: порядок розыгрыша меняет остаток колоды и доступную информацию.

## Обход очереди

Функция `playState(state)` возвращает оптимальное EV из информационного состояния. На каждом вызове рассматривается `queue[0]`.

1. Если очередь пуста, вызывается `settle(finished, shoe)`.
2. Если `needsCard:true`, для каждой публичной карты строится ветвь через условное распределение `publicDraws`. Карта удаляется из остатка, флаг снимается, длина становится `2`, затем вызывается `playState`.
3. Если рука перебрала, достигла Charlie, получила 21, является разделённым тузом с правилом одной карты или закончилась после DOUBLE, она переносится из `queue` в `finished`.
4. Для обычной руки доступны STAND, HIT и разрешённый DOUBLE. HIT удаляет одну публичную карту и оставляет руку в начале очереди. DOUBLE доступен только на первых двух картах; после него ставка становится `2`, выдаётся ровно одна карта, затем рука переносится в `finished`.
5. Если текущая рука образует пару, проверяются `splitPolicy`, `maxSplitHands` и `resplitAces`. При разрешённом SPLIT текущая рука удаляется из очереди, две дочерние руки с базовой картой добавляются в начало очереди в порядке `left`, `right`, обе с `needsCard:true`. Это действие не удаляет дополнительную карту из `shoe`: две исходные карты уже были видимыми и удалены при входе в состояние.

SURRENDER остаётся действием только исходной двухкарточной руки, если это уже поддерживается выбранной моделью. После SPLIT сдача не добавляется автоматически: это отдельное правило, которое нельзя выводить из `maxSplitHands`. Страховка также не входит в generic settlement и продолжает считаться отдельным pre-peek экспериментом.

Для каждого действия используется максимум по EV. Все ветви карты используют условное распределение, в котором скрытая карта дилера остаётся неизвестной. При `peek:true` запрещённые natural hole cards исключаются из posterior; при `peek:false` они остаются возможными до settlement.

## Разделённые тузы

`splitAcesOneCard:true` завершает каждую руку, получившую одну карту после разделения тузов. В таком состоянии HIT, DOUBLE и повторный SPLIT не добавляются. Если конкретные правила разрешают повторное разделение тузов, это должно задаваться отдельно `resplitAces:true`; сам `splitAcesOneCard` не должен молча разрешать resplit.

После разделения тузов две обычные карты `A+10` не получают выплату за натуральный блэкджек. Они считаются обычной суммой 21 при settlement. Это правило уже отражено в assumptions текущей модели и должно остаться явным в generic state.

## Settlement дилера

После того как все руки стали терминальными, скрытая карта дилера усредняется один раз для конечного остатка. Для каждого допустимого hole строится точное распределение дилера по S17/H17, затем результат применяется к каждой руке. Повторное использование одного распределения допустимо из-за линейности ожидания; корреляция рук не теряется, потому что общий остаток уже фиксирован до settlement.

Порядок правил:

1. Перебор руки игрока всегда даёт `-bet`.
2. Натуральный блэкджек дилера имеет приоритет над обычной 21 и Charlie.
3. При `peek:true` natural hole уже исключён из posterior.
4. При `peek:false` и `dealerBJSettlement:'loseAll'` natural дилера даёт `-sum(all bets)`, включая ставки всех resplit рук и DOUBLE.
5. При `dealerBJSettlement:'originalOnly'` natural дилера даёт `-1` за исходную единицу; дополнительные split/DAS единицы возвращаются согласно OBO-модели. Это должно применяться независимо от числа рук.
6. После отсутствия natural дилера каждая неперебравшая руку получает `+bet`, `0` или `-bet` по сравнению с одним результатом дилера. Charlie без перебора даёт `+bet` против обычного дилера, но не против natural.
7. Обычная 21 после SPLIT не получает `blackjackPayout`; `blackjackPayout` применяется только к исходной двухкарточной натуральной руке до SPLIT.

Если все руки уже перебрали и режим `loseAll` или успешный `peek` делает исход однозначным, settlement можно вернуть сразу. Для OBO необходимо сохранить факт natural дилера даже в этом быстром пути.

## Ограничения и проверка входа

`validateRules` должен нормализовать:

```text
maxSplitHands: integer 1..4
resplit: maxSplitHands > 2
resplitAces: boolean
doubleAfterSplit: boolean
splitAcesOneCard: boolean
charlieAfterSplit: boolean
```

Несовместимые варианты нужно отклонять до запуска Worker: `maxSplitHands < 2` при запросе SPLIT, `resplitAces:true` при `splitAcesOneCard:true` если правила приложения не определяют такое поведение, а также раннюю сдачу вместе с несовместимым `peek`. Нехватка карт для скрытой карты или обязательного добора должна завершать расчёт ошибкой без числа EV.

## Aggregate edge

Generic solver может вернуть `actions.splitFull` для одной исходной пары. В aggregate edge полное SPLIT нельзя включать по умолчанию: каждый из сотен начальных сценариев может запускать отдельное дерево с четырьмя руками. Без общего кеша по `(shoe, up, rules, queue)` это превысит лимит времени.

Безопасный интерфейс:

- `includeSplit:false` по умолчанию сохраняет текущий edge без полного SPLIT;
- `includeSplit:true` разрешается только для малого остатка или явно увеличенного лимита;
- каждый сценарий учитывается только после `exact:true`;
- тайм-аут любого обязательного сценария делает aggregate edge `unavailable`, без усреднения неполного набора;
- restricted `splitTwoCardStop` и полный `splitFull` показываются разными строками.

## Диагностика

В отчёт generic solver добавить `maxSplitHands`, `handsCreated`, `maxQueueLength`, `maxSplitDepth`, `splitTransitions`, `resplitTransitions`, размеры и вытеснения кешей, а также последний этап (`deal-child`, `player-decision`, `resplit`, `dealer-recursion`, `settlement`). Эти поля позволяют отличить нехватку карт от превышения времени и от взрыва числа состояний.

## Тестовый план

1. Сохранить `tests/full_split_oracle.cjs` как регрессию для `maxSplitHands:2`. Все 24 сценария должны совпасть с текущим `solveSplit` и независимым oracle.
2. Добавить малую колоду с одной парой и остатком, где повторный SPLIT невозможен; generic result должен совпасть с no-resplit.
3. Добавить малую колоду для `8,8` с третьей восьмёркой: `maxSplitHands:2` запрещает resplit, `maxSplitHands:3` создаёт третью руку, `maxSplitHands:4` не создаёт её без выгодного решения.
4. Проверить монотонность: при одинаковых правилах и возможности не делать resplit оптимальный EV с `maxSplitHands:4` не ниже EV с `maxSplitHands:2`.
5. Проверить четыре руки, исчерпание остатка, невозможный hole, A+A с one-card rule, resplit aces, DAS, Charlie после SPLIT и обычную 21 без blackjack payout.
6. Проверить `loseAll` и `originalOnly` при natural дилера после двух, трёх и четырёх рук; проверить `peek:true` и `peek:false` отдельно.
7. Проверить ключи кеша перестановкой очереди, различиями `bet`, `length`, `needsCard` и `splitDepth`; результаты не должны смешиваться.
8. Для aggregate edge добавить малый независимый oracle, где перечисляются все начальные пары, upcard, hole и дерево resplit. Большой восьмиколодный edge должен возвращать `unavailable` по лимиту, а не частичный ответ.

## Порядок внедрения

Сначала вынести текущую двухрукую логику в generic queue при `maxSplitHands:2` и добиться полного совпадения с существующими тестами. Затем включить resplit для малых остатков и только после независимого oracle поднять лимит до `4`. Aggregate edge и интерфейс следует подключать последними, когда generic solver умеет честно сообщать `exact`, `timeout` и `unavailable`.
